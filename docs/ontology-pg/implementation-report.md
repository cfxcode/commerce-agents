## 已实现

新增本体/观察、确定性补货、统一执行服务、串行调度、预览内容绑定、原子模拟提交、幂等及回执验证；接入冻结 PG、三值谓词、局部图指导和降级；提供只读中英文调试页、可重置评测、候选检查、发布及回滚命令。人工图已在本地发布；当前零售配置开启 P 模式，指导超时上限为 30 秒。

原始完整结果：[C0](results/pilot-C0.json)、[O](results/pilot-O.json)、[T](results/pilot-T.json)、[P](results/pilot-P.json)。表中的 token 包含已返回的输入、输出和缓存读取；不代表金额。初版记录器未获取失败指导调用的 usage，因此 T/P 的 token 只能作为下界；现有代码已显式标记未计量调用，候选不能以不完整成本证据发布。

首轮总计 81/96 通过，没有观察到越权应用或重复副作用。每组在 T03（商品族）、T11（过期源数据）、T19（并发冲突）均保持了正确库存和变更数量，但任务状态未收束到相应终态，按冻结 oracle 判为失败。另有 O/T23 模型接口错误、T/T10 读取超时和 P/T10 总任务预算耗尽。

P/T10 的原始报告将超时放入 infrastructure_error；根据 120 秒总预算及异常类型，它应归类为任务预算失败。当前评测器已经区分 task_error 与基础设施错误。此处保留原始报告，主表使用全部提交数作为分母，不通过排除失败提高成绩。

**本次试评没有证明 PG 提高成功率。** T/P 增加了延迟，8 秒指导超时下存在频繁降级。单次小样本试评不支持统计显著性或泛化提升结论；初始验收据此将指导默认关闭，后续运行配置另行开启 P 模式。

## 指导校验与页面恢复修复

真实模型复现确认，原有字符串检查会把“不能声称已批准”误判为批准声明。校验器现在识别明确的否定式提醒，继续拒绝肯定式授权声明、伪造引用和改变权限的指令；指导提示词提供完整输出 schema，并明确暂存和应用的区别。失败事件记录错误类别、字段路径及实际耗时；失败的模型文本保存在私有诊断记录中，不进入前端或后续模型请求。

修复后，开始、评估、计算完成和等待批准四个阶段的真实指导调用全部成功；完整只读对话中的五次指导调用也全部成功，检查前后库存不变。另一次交互补货任务的五次指导均成功，随后通过宿主批准并验证库存。上述小规模检查用于确认修复，不替代原始 96 次试评，也不证明总体成功率提升。

调试页显示最近指导的成功／降级次数、失败原因和明确标注的历史指导。会话连接失败时显示服务地址与重试入口，启动会话的请求在 10 秒后超时。零售页面构建、类型检查、中英文检查，以及指导面板的当前／历史／关闭状态渲染检查通过。

## 离线候选

首次 Refiner 返回了不符合补丁 schema 的输出，已拒绝。补全严格输出 schema 后，第二次返回合法空 operations，原因是训练子集全部通过、聚合诊断不足以支持具体图修改。因此保持人工 PG，没有发布 E 版本。

记录见 [candidate-history.jsonl](results/candidate-history.jsonl)。两次 Refiner 调用分别报告 6,065 输入 / 1,510 输出和 6,428 输入 / 635 输出 token；它们属于离线成本，未混入在线对照表。候选接受、拒绝、等价去重、成本门槛、版本哈希和回滚通过合成测试验证，不把合成接受记录描述为真实优化收益。独立验证/最终测试语料未用于图选择，尚未进行真实模型留出评测。
